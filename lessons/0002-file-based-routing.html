File-based routing & the route tree

~12 min · Mapping your React Router instincts onto TanStack Router. Cheat sheet: Routing reference.

← 0001: Execution model Cheat sheet →

You want to look at the Talsek Start routes/ folder and know the URLs it serves — well enough to spot it when AI files a route in the wrong place or links to a URL that doesn't exist. That skill is one convention table away, and you already know the underlying idea from React Router.

The shiftFilename is the config

In React Router you declare routes as config — a tree of <Route path="/about"> elements or a createBrowserRouter object. In TanStack Router the filename is the path, and a code generator turns your routes/ folder into the route tree for you. 

// React Router: you write the tree
<Route path="/about" element={<About />} />
<Route path="/posts/:postId" element={<Post />} />

// TanStack Router: the files ARE the tree
//   routes/about.tsx           -> /about
//   routes/posts/$postId.tsx   -> /posts/:postId
// (routeTree.gen.ts is generated from these — you never write it)

So there is no central routing file to edit. To add a route you add a file; to move it you move the file; the tree regenerates. That generated file is src/routeTree.gen.ts in this repo — open it and you'll see it's stamped “automatically generated… do NOT edit.”

The conventionFilename → URL

One table covers ~90% of what you'll see (every example here is from this repo):

Two ways to nest: a folder (auth/callback.tsx) or dot-notation (apply.$token.tsx) — same URL. (File Naming Conventions)

The one that trips peoplePathless routes

Files starting with _ are pathless layout routes: they wrap their children but add no segment to the URL. They exist to share layout and logic — exactly like a parent layout route in React Router, minus the URL. (Routing Concepts)

This repo uses two. _marketing.tsx wraps the public site (home, pricing, contact); _member.tsx wraps the signed-in app (dashboard, candidates, billing) and runs the auth guard from Lesson 0001. Their children render inside the layout's <Outlet/> and inherit that logic.

Route ID vs URL

A pathless child has two different “paths”, and confusing them is the #1 routing bug:

Route ID (tree position)URL users visit
_member/dashboard.tsx/_member/dashboard/dashboard

The string you pass createFileRoute('/_member/dashboard') is the tree position — pathless segments included. The URL is that with pathless segments stripped.

CodegenYou don't write the tree

The generated routeTree.gen.ts wires parents to children from the folder structure. Look at it and you'll see the pathless trick in action:

const MemberRoute = MemberRouteImport.update({
  id: '/_member',                 // no `path` field -> pathless
  getParentRoute: () => rootRouteImport,
} as any)
// MemberDashboardRoute gets path: '/dashboard' but parents onto MemberRoute

_member has an id but no path — that's literally how codegen marks it pathless. Its children get the real URL while parenting onto the layout. Type-safety flows from this generated tree: Route.useParams(), <Link to>, and loader returns are all inferred from it — which is why you must never hand-edit it.
