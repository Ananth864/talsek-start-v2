File-based routing & the route tree

Filename → URL → tree position. Companion to Lesson 0002. Primary sources: File Naming Conventions, Routing Concepts.

The filename is the config. You never hand-write the route tree — codegen reads your routes/ folder and builds routeTree.gen.ts for you.

Dot-notation and folders are interchangeable for nesting: apply.$token ≡ apply/$token in URL terms.

Pathless routesThe underscore prefix

Rule

A segment prefixed with _ (e.g. _member, _marketing) is a pathless layout route. It does not add a segment to the URL. It exists to wrap its children (via <Outlet/>) and run shared logic — guards, layouts, providers.

Route ID / tree positionURL users visit
_member/dashboard.tsx/_member/dashboard/dashboard

That gap is the whole trick. The string you pass createFileRoute('/_member/dashboard') is the route's identity in the tree (pathless segments included); the URL is derived by stripping the pathless segments.

FoldersFour kinds — don't confuse them

A folder does very different things depending on its name. The naive “a folder groups pages under shared logic” model is wrong — a plain folder shares nothing:

KindExampleURL?Shared layout/logic?
Plain folderapi/yesNo — just organises
Layout route (pathed)docs.tsx  or  docs/route.tsxyesYes — wraps children via <Outlet/>
Pathless layout_member.tsx  or  _member/route.tsxNoYes
Route group(app)/NoNo — pure organisation

Want shared logic/layout without a URL segment? Reach for a pathless layout (_ prefix) — that's exactly what _member (authed) and _marketing (public) are. A plain folder won't share anything.

API routes are not pages

api/webhooks/dodo.ts → /api/webhooks/dodo and api/cron/billing-auto-refill.ts → /api/cron/billing-auto-refill are server endpoints, declared with server.handlers (no component). docs/$.tsx → /docs/* uses a splat to serve any docs path from one route. Covered in Lesson 0005.

- excludes a file

A --prefixed file (-table.tsx) or folder is ignored by codegen — handy for colocating components/utils inside routes/ without making them routes.

CodegenrouteTree.gen.ts

  • Auto-generated by the Vite plugin (or tsr generate). Never edit it — it's overwritten.
  • It wires each route's getParentRoute from the folder structure.
  • The createFileRoute('/...') path must match the file's tree position, or codegen/typecheck fails.
  • Type-safety flows from it: Route.useParams(), <Link to>, loader return types are all inferred.
// from this repo's routeTree.gen.ts:
const MemberRoute = MemberRouteImport.update({
  id: '/_member',                 // no `path` field -> pathless
  getParentRoute: () => rootRouteImport,
} as any)
as any in the gen file is normal

The file starts with // @ts-nocheck and uses as any on its wiring because the route-tree generics are recursive and too complex to generate cleanly. The real type-safety lives in each createFileRoute('/...') path string (it gives TypeScript your file identity) and the declare module Register { router } in router.tsx. Never import types from routeTree.gen.ts — and don't treat its as any as permission to use as any yourself.

What getParentRoute is for

It wires the parent-child edge. Along it flow: rendering (<Outlet/>), loader data, beforeLoad context, search-param schemas, and accumulated types. It's a thunk (() => Parent) to defer resolution past circular initialisation. Codegen writes it from your file structure — you almost never do.

Red flagsWhat to catch in AI output

Hand-editing routeTree.gen.ts

If AI proposes a change inside routeTree.gen.ts, reject it. Add/rename a file under routes/ instead and let codegen regenerate.

createFileRoute path doesn't match the file

_member/dashboard.tsx must call createFileRoute('/_member/dashboard') — not ('/dashboard'). A mismatch breaks codegen/typecheck. The arg is the tree position, including pathless segments.

Linking to a pathless segment

<Link to="/_member/dashboard"> is wrong — the URL has no _member. Link to /dashboard. (AI gets this wrong often.)
