Glossary

The shared vocabulary of these lessons. Adhered to everywhere. Seeded from lessons 0001–0002; grows each lesson.

Lesson 1Execution model

Isomorphic
Code that runs in (and is bundled for) both server and client. The Start default.
SSR (Server-Side Rendering)
The server produces the first HTML; the browser hydrates it into an interactive app.
Hydration
The browser attaching React's event handlers to server-rendered HTML.
RPC (Remote Procedure Call)
Calling a server function from the client looks like a local call but crosses the network. createServerFn is Start's RPC.
Server function
A createServerFn — runs on the server, callable from the client. Start's replacement for hand-rolled API endpoints.
Server-only function
A createServerOnlyFn — runs on the server, throws if called from the client. A simple wrapper (takes the fn directly).
Client-only function
A createClientOnlyFn — runs in the browser, throws during SSR.
Import protection
Mechanism that keeps code out of the wrong bundle: *.server.ts / *.client.ts suffixes, or server-only / client-only side-effect imports.
Loader (isomorphic)
A route's data-fetch hook. In Start it runs on the server (SSR) and the client (navigation) — not server-only.
Module scope
Code at the top level of a file, run once at import/build time. Reading process.env here leaks to the client bundle.

Lesson 2Routing

Route tree
The nested structure of all routes. Built by codegen into routeTree.gen.ts — never hand-written.
Codegen
The Vite plugin (or tsr generate) that scans routes/ and emits routeTree.gen.ts.
File-based routing
Routing where the filename declares the path — no central config object.
Root route (__root.tsx)
The top-level route that wraps every page; holds the document shell, providers, global head().
Index route (index.tsx)
The route for a folder's root URL. At routes/ it's /; at routes/posts/ it's /posts.
Static route
A fixed URL segment, e.g. about.tsx → /about.
Dynamic route / param ($id.tsx)
A URL segment that matches any value, exposed as params.id.
Splat route ($.tsx)
A catch-all matching multiple trailing segments (/*).
Pathless layout route (_foo.tsx)
A route prefixed with _ that adds no URL segment. Wraps its children via <Outlet/>; used for shared layout / guards.
Layout route (pathed, posts.tsx)
A route file that shares layout/logic with its children and contributes its segment to the URL. Inside a folder, the layout file is route.tsx. Distinct from a pathless layout (no URL) and a plain folder (no logic).
Plain folder (posts/)
Structures the URL and organises files. Does not share layout/logic by itself — that needs a layout route.
Route group ((app)/)
A parenthesised folder: pure organisation. No URL segment, no layout, no effect on the tree.
Excluded file (-foo.tsx)
A --prefixed file/folder ignored by codegen — for colocating non-route modules inside routes/.
API route (api.x.ts)
A route that is a server endpoint, not a page — declared with server.handlers instead of component. Runs on the server.
getParentRoute
The codegen-wired link from a child to its parent. Along it flow: rendering (<Outlet>), loader data, beforeLoad context, search-param schemas, and accumulated types. Users rarely write it; parentage comes from file structure.
Gen file (routeTree.gen.ts)
Auto-generated route tree. Carries // @ts-nocheck + as any on its wiring; the real types live in each createFileRoute path string and the Register declaration. Never hand-edit or import types from it.
Route ID (vs URL path)
The route's identity in the tree, including pathless segments — e.g. /_member/dashboard. The URL (/dashboard) strips the pathless segment.
Outlet
Where a parent/layout route renders its matched child. Same name as React Router.

Lesson 3Server functions

Server function pipeline
The ordered stages of a createServerFn: { method } → .validator() → .middleware() → .handler(). Only the handler is required.
Validator (.validator(fn))
Parses + validates the caller's input; its return becomes the typed data downstream stages see. No validator → no data.
Server-function middleware (.middleware([...]))
Runs before the handler and merges values into context (e.g. a session). Built with createMiddleware({ type: 'function' }).client().server().
Handler (.handler(({ data, context }) => ...))
The server-only logic. Returns a serialisable value across the RPC.
Method ({ method: 'GET' | 'POST' })
GET for cacheable reads; POST (the default) for mutations.
API route (vs server function)
A server endpoint with a real URL + HTTP method (server.handlers). Pick it when an external caller needs a URL; pick a server function for typed app-to-server calls.
